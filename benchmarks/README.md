# Бенчмарки

Небольшие программы, каждая делает одну типичную работу много раз. Каждая задача
написана на FoxLang (`foxlang/`), Python (`python/`), Lua (`lua/`), Ruby (`ruby/`) и
JavaScript (`javascript/`).

| Бенчмарк         | Что делает                                                   |
|------------------|--------------------------------------------------------------|
| `fib`            | рекурсивно считает 27-е число Фибоначчи (вызовы функций)     |
| `loop`           | три миллиона раз считает остаток от деления и складывает     |
| `array_sum`      | добавляет полмиллиона чисел в массив и складывает их         |
| `map_lookup`     | кладёт в словарь 200 000 ключей и находит каждый              |
| `split_join`     | склеивает 200 000 строк через запятую и режет обратно         |
| `records`        | создаёт 300 000 структур из двух полей и читает поля          |
| `sort_numbers`   | сортирует 300 000 чисел встроенной сортировкой                |
| `json_roundtrip` | превращает 50 000 записей в JSON и разбирает обратно          |

Каждая программа печатает контрольное число. У всех языков оно обязано совпасть с
FoxLang, иначе запуск падает: быстрее за счёт меньшей работы не получится. Первый
аргумент программы меняет размер задачи.

## Запуск

```bash
python3 benchmarks/run.py                               # build/foxlang и другие языки
python3 benchmarks/run.py --foxlang путь/к/foxlang      # другая сборка
python3 benchmarks/run.py --baseline путь/к/старому     # сравнить две версии
python3 benchmarks/run.py --only-foxlang --runs 3       # только FoxLang, 3 запуска
python3 benchmarks/run.py --smoke                       # один раз на маленьких входах
python3 benchmarks/run.py --json результат.json         # сохранить результаты
```

Каждая программа запускается `--runs` раз (по умолчанию 5) по очереди с остальными,
в зачёт идёт лучшее время. Язык, которого нет на машине, пропускается; `--require ruby`
делает его обязательным. Программа, не уложившаяся в `--timeout` секунд, помечается
как «timeout».

## Проверка перед выпуском

Задание `benchmarks` в `.github/workflows/build.yml` скачивает предыдущий выпуск и
запускает `run.py --baseline` на той же машине. Если новая сборка на каком-то
бенчмарке медленнее больше чем на `--max-slowdown` (10%) и больше чем на `--noise`
(0,03 с), выпуск не публикуется. Если замедление осознанное, выпуск запускают вручную
(Actions → Build and Auto Release → Run workflow) с флажком `allow_slower`.

Результаты уходят в выпуск файлом `benchmarks.json`, а сайт после выпуска берёт их
оттуда и рисует графики.

## Новый бенчмарк

1. `foxlang/<имя>.fox`: первая строка — комментарий о том, что измеряется; в конце
   `print` контрольного числа.
2. Та же программа в других папках с тем же именем. Если в языке нет нужного в
   стандартной библиотеке (у Lua нет JSON), файл просто не пишется.
3. `python3 benchmarks/run.py --smoke` должен пройти.

Имя файла не должно совпадать с модулем стандартной библиотеки (`arrays`, `string`,
`json` и т.д.): `using arrays;` сначала ищет файл рядом с программой.
