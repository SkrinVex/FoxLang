# Проверка и гарантии графического установщика

Актуальные результаты для конкретного коммита находятся в
[PR #32](https://github.com/SkrinVex/Skrumi/pull/32),
[обычном CI](https://github.com/SkrinVex/Skrumi/actions/workflows/ci.yml) и
[release workflow](https://github.com/SkrinVex/Skrumi/actions/workflows/build.yml).
Версия исходников берётся из `VERSION`. Наличие стабильного установщика определяется
по assets [GitHub Releases](https://github.com/SkrinVex/Skrumi/releases/latest),
а не по номеру версии в исходниках или успешной локальной сборке.

## Архитектура

- VM, компилятор и интерпретатор сохраняют архитектуру и существующие API.
  Новые общие примитивы зарегистрированы через BuiltinSpec и доступны LSP.
- Канонические новые модули используют `.skm`; проверяемые `.fox`-адаптеры
  сохраняют совместимость. Современный импорт предпочитает `.skm`, старый `.fox`
  сохраняет прежний приоритет, явное расширение не подменяется.
- Публичные API предоставляют проверяемые файловые операции, блокировки, SHA-256,
  USTAR, процессы с выводом/тайм-аутом/отменой, платформенные каталоги, планы PATH,
  строковые значения пользовательского реестра и встроенные ресурсы.
- `std/ui.skm` предоставляет ProgressBar, диалоги, темы, стили и масштабируемые
  контролы. Общий FreeType-рендерер поддерживает TTF/OTF; старый пиксельный текст
  остаётся доступен. Builder сохраняет старые проекты и экспортирует `.skm`.
- Playground использует тот же runtime. Недоступные системные операции возвращают
  ошибки; переносимые UI-функции проверяются в реальном WebAssembly и Chromium.
- Прикладная логика полностью находится в `installer/main.skm`, `transaction.skm`,
  `integration.skm`, `legacy.skm`: GUI, владение файлами, staging, backup, журнал,
  обновление, удаление, PATH, регистрация, проверка CLI, отмена и восстановление.
  Специализированного C++ движка установки нет. Python используется в сборке и тестах.
- Standalone-контейнер v2 содержит программу и ресурсы, читает старый v1.
  Runtime, CLI/LSP, совместимые команды, `std`, manifest, логотип и лицензированный
  шрифт входят в офлайн-поставку. Windows также содержит программу обслуживания
  на Skrumi. Подробнее: [GUI_INSTALLER.md](GUI_INSTALLER.md).

## Обязательные проверки кандидата

| Платформа | Проверки |
|---|---|
| Windows runner | Регрессии языка, Unicode, shell-free процессы, реестр и PATH, standalone, настоящий GUI/resize/close/cancel, точный дистрибутив, зарегистрированная команда удаления, bounded NTFS volume и заблокированный файл |
| Linux runner | Регрессии языка и OS, X11 GUI/resize/close/cancel, точный дистрибутив, изолированный tmpfs с нехваткой места и отказом записи |
| Portable Linux | Статическая musl-сборка и тесты в Alpine, standalone/GUI и установка на Ubuntu без предустановленного Skrumi |
| Web | Реальный WASM, примеры, generated Builder code, диалоги/закрытие/стили/размеры, недоступность desktop API, Chromium desktop/mobile |
| Android | SDK и APK для четырёх ABI, проверка упаковки и 16 KB, runtime на эмуляторах API 28/35 |
| Release | Benchmarks против предыдущего stable, точный состав assets, два GUI-бинарника, сохранение Android/editor assets, отсутствие новых ZIP/TAR-пакетов языка |

Тесты установщика проверяют чистую и повторную установку, обновление, выбор LSP,
отмену до начала и во время обновления, повреждённый payload/CLI, конфликт записи,
принудительное завершение процесса перед commit, восстановление, удаление,
сохранение пользовательских файлов и миграцию старых ownership manifests.
Сравниваются реальные байты, команды, записи реестра/профиля и пиксели окна.
Проверяются также отказ durable commit и сохранение неизвестных staging-файлов.

Полный [dry run c42d88f](https://github.com/SkrinVex/Skrumi/actions/runs/39016885872)
прошёл все зависимые jobs, включая Windows, Android и inventory, без публикации.
Для последующих изменений нужно смотреть результаты их собственных запусков;
успех этого контрольного прогона не заменяет проверку нового кода.

Скриншоты GUI сохраняются в CI. Linux-снимки проверены вручную, включая разные
размеры окна. В рабочем окружении разработки скачивание Windows artifacts было
заблокировано сетью; ручной просмотр Windows-снимков не заявляется.

## Границы гарантий

- Установка не атомарна целиком: между заменами отдельные файлы могут быть
  недоступны. Не запускайте CLI во время обновления. Долговечность зависит от ОС,
  файловой системы и накопителя; ошибка синхронизации может последовать после
  видимого изменения. Журнал содержит намерение до изменения файлов.
- SHA-256 проверяет вложенный manifest, но не удостоверяет издателя executable.
  Проверка ссылок не исключает конкурентную подмену каталогов сторонним процессом.
- Чужие изменения сохраняются. При конфликте восстановление оставляет журнал и
  backup для ручного разрешения. Конфликт PATH/реестра не мешает вернуть прежние
  бинарники. Недоступный журнал нельзя обходить небезопасным откатом.
- Пустые каталоги и lock-файл могут остаться. Повреждённый журнал либо неизвестное
  содержимое области без журнала требуют ручного разбора. Неизвестные файлы не
  удаляются автоматически. Ошибка очистки после commit не уничтожает проверенную
  рабочую установку: выдаётся предупреждение, журнал остаётся для повторной очистки.
- Windows maintenance executable и его ownership-файл намеренно остаются после
  удаления для восстановления. Прежние внешние интеграции редакторов/PATH при
  импорте legacy-установки сохраняются, если их владение нельзя доказать.
- GUI-поставка поддерживает x86_64 Windows и Linux с X11/XWayland. Окно изменяет
  размер; минимальная клиентская область 480×348. Автоматическое переключение DPI
  при переносе между мониторами не реализовано. Android и браузер не предоставляют
  desktop installation API.

Release workflow не публикует кандидат при ошибке любой обязательной зависимости.
Ручной `publish=false` создаёт внутренний `verified-release` без тега. Публикация
нового stable разрешена только с `master`; исторические релизы и GitHub source
archives не изменяются. Кнопки сайта появляются только для существующих assets.
