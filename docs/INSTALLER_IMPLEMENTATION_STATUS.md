# Состояние работ над нативным установщиком

**Установщик не реализован и не готов к выпуску.** Этот набор изменений добавляет
проверяемые общедоступные примитивы; он не выполняет установку Skrumi. Нельзя менять
основные ссылки скачивания, удалять старые assets или публиковать GUI-установщик на
основании этих изменений. VERSION пока сохранён: повышение версии и публикация
должны сопровождать законченный, проверенный состав поставки.

## Карта архитектуры и зависимостей

- `src/core/Compiler.cpp`, `Vm.cpp`, `Runtime.cpp`, `Interpreter.cpp`: регистровая
  VM и общий runtime. Изменение семантики языка для добавленных API не требуется.
- `src/core/builtins/Registry.cpp`: единый каталог BuiltinSpec, используемый
  runtime, семантическим анализатором и LSP. Новые примитивы зарегистрированы здесь;
  подсветка редакторов синхронизирована через `packaging/sync_editor_builtins.py`.
- `std/fs.skm`, `os.fox`, `env.fox`: уже существуют файловые операции, аргументы,
  запуск процессов без shell и окружение процесса. Не нужен параллельный модуль
  system. Обновлённые реализации используют `.skm`; `.fox`-адаптеры сохраняют старые пути.
- `std/ui.skm`: immediate-mode компоненты на Skrumi; `Surface.cpp`, `Ui.cpp` и
  `Window.cpp` обеспечивают общий рисунок, фокус/модальность и платформенные события.
  Новый ProgressBar и Dialog используют эту систему. Шрифт остаётся пиксельным;
  автоматическое масштабирование под DPI не реализовано.
- `src/standalone/Bundle.cpp`, `Image.cpp`, `Build.cpp`: существующая упаковка
  источников и runtime в ELF/PE, проверка структуры и CRC, лимит payload 64 МиБ.
  Общий механизм `--resources` теперь упаковывает бинарные ресурсы с проверкой
  структуры, предельных размеров и отказом от ссылок. Конкретный payload
  установщика CLI/LSP и его manifest ещё не сформированы.
  CRC структуры не заменяет криптографическую проверку установочного payload.
- `site/builder/model.js`: формат проекта 1, генератор `.skm` с сохранением
  пользовательского main; новые необязательные поля прогресса/темы совместимы со
  старыми проектами. Настройка диалогов и событий закрытия в редакторе ещё нужна.
- `src/web/Playground.cpp`: тот же runtime через Emscripten; Asyncify для графики.
  Новые UI-примитивы работают в этой сборке. `fs_write_atomic` явно недоступен;
  остальные файловые функции ограничены виртуальной FS.
- `packaging/windows/*`, `packaging/linux/install.sh`: текущая установка через
  скрипты. Она не заменена .skm-установщиком и не считается выполнением задачи.
- `.github/workflows/build.yml`: tar/zip используются также benchmark job.
  До отказа от пользовательских архивов нужно выделить внутренний артефакт CLI/LSP
  и заменить получение предыдущей версии для сравнительных замеров.
- `.github/workflows/android.yml`, `android/`, `packaging/build_android.py`:
  Android SDK и APK собираются из исходников. Существующие AAR/APK и их имена
  совместимости должны сохраняться. Android-сборка этих изменений ещё не проверена.
- `cmake/Version.cmake`: VERSION — единственный источник версии, метаданные
  редакторов обновляются на configure; данные сайта — через `site_facts.py`.
  Для законченного совместимого расширения уместно minor-повышение.

## Добавленные проверяемые возможности

- `fs_read_checked`, `fs_write_atomic`, `fs_mkdtemp`, `path_safe_join`, обёртки в fs,
  реальные системные ошибки, UTF-8 пути, отказ от ссылок/reparse points.
- Ограничение stdout существующего API и отказ от NUL в аргументах процессов.
- Отменяемые запросы закрытия, объединение повторных запросов, сохранение прежнего
  поведения при отключённом перехвате, отдельная обработка уничтожения окна.
- ProgressBar с диапазоном, процентами и неопределённым состоянием; неблокирующие
  информационные/ошибочные/подтверждающие диалоги; общая светлая/тёмная палитра.
- ProgressBar и тема создаваемого приложения в Builder; пример в Playground.
- Канонические `std/ui.skm`, `std/fs.skm`, `std/graphics.skm` и совместимые
  `.fox`-адаптеры; приоритет расширения определяется импортирующим файлом.
- Новый `std/resources.skm`, контейнер ресурсов v2 с чтением v1 и потоковый SHA-256.
- Нативные проверки реальных пикселей и событий окна; проверки в WebAssembly и
  Chromium. Новые desktop-тесты включены через CTest в существующую Windows/Linux
  матрицу. Новый WebAssembly-тест добавлен в `ci.yml` и `pages.yml`.

Документированные ограничения новых файловых функций: проверка ссылок не защищает
от конкурентной подмены каталогов; `write_atomic` заменяет метаданные файла;
ошибка синхронизации после rename может означать уже видимое новое содержимое.
Не следует использовать эти примитивы как готовую многокомпонентную транзакцию.

## Оставшиеся этапы (в порядке зависимостей)

1. Публичные API архитектуры/платформенных каталогов, пользовательского PATH с
   сохранением и отменой только собственных изменений, регистрации удаления Windows.
2. Захват stdout/stderr вместе с exit code, тайм-ауты и неблокирующая модель
   длительных операций, которая не вызывает Skrumi VM из чужого потока.
3. Распаковка с отказом от traversal/ссылок (публичный `fs_sha256` уже добавлен);
   безопасная публикация файлов, журнал и гарантии синхронизации на обеих ОС.
4. Собрать installer payload поверх проверенного общего `--resources`. Проверки
   упаковки и запуска вне исходного cwd выполнены на Linux; Windows ещё не проверен.
5. Проект установщика `.skm`: интерфейс с оригинальным знаком, параметры, журнал,
   реальные этапы, пофайловое владение, staging/backup и проверка установленного CLI.
6. Транзакции `.skm`: cancel, ошибки, обнаружение незавершённого журнала, восстановление
   после аварии, безопасное обновление и удаление с сохранением изменённых/чужих файлов.
7. Builder: редактирование событий закрытия/диалогов и более полная настройка стилей;
   UI: масштабирование и типографика для законченного установщика.
8. Матрица тестов установки Windows/Linux, включая нехватку места, повреждённый
   payload, ошибки записи, обновление, отмену, аварийное восстановление и удаление.
9. Перенос внутренних потребителей архивов, новая публикация assets, фактические
   ссылки скачивания, документация установки и согласованное повышение версии.

Не выполнены: установка, обновление, удаление, откат, PATH, выпуск установщиков.
Нет оснований утверждать, что прикладная логика установщика написана на Skrumi:
исходников установщика пока нет. Добавленные UI-компоненты действительно написаны
на Skrumi; C++ содержит только общие runtime/платформенные примитивы.
