# Состояние нативного установщика

**Работа продолжается; стабильный GUI-релиз ещё не опубликован.** PR #32 остаётся
черновиком. Подготовлены minor-повышение `VERSION`, новый состав release assets и
страница загрузки с проверкой фактически опубликованных файлов. Новая release
цепочка должна пройти сборку кандидата без публикации.

## Архитектура

- `Compiler.cpp`, `Vm.cpp`, `Runtime.cpp`, `Interpreter.cpp` сохраняют существующую
  архитектуру языка. Общие примитивы регистрируются через BuiltinSpec и доступны LSP.
- Канонические модули `std/fs.skm`, `os.skm`, `env.skm`, `graphics.skm`, `ui.skm`,
  `resources.skm` содержат публичные обёртки. Старые `.fox` — проверяемые адаптеры.
  Импорт из `.skm` предпочитает `.skm`, из `.fox` — `.fox`; явное расширение сохраняется.
- Общие C++ API предоставляют проверяемые файловые операции, блокировки, SHA-256,
  безопасную распаковку USTAR, платформенные каталоги, пользовательское окружение
  Windows и процессы с раздельными stdout/stderr, тайм-аутом и отменой.
- `std/env.skm` формирует обратимые планы PATH. Windows сохраняет тип значения
  реестра; Linux меняет поддерживаемый login-профиль. Чужие последующие правки
  не перезаписываются. Текущая оболочка не считается автоматически обновлённой.
- `std/ui.skm` содержит ProgressBar, диалоги, темы, стили, перенос и прокрутку
  сообщений. Общий рендерер поддерживает необязательные масштабируемые TTF/OTF
  через FreeType; прежний пиксельный текст сохраняется по умолчанию.
- `site/builder/model.js` сохраняет формат проекта 1 с необязательными новыми
  полями: прогресс, диалоги, закрытие, тема и стили. Генератор выдаёт `.skm`.
- `src/web/Playground.cpp` использует тот же runtime. Недоступные системные
  операции возвращают явную ошибку; переносимый UI проверяется в WebAssembly.
- Standalone-контейнер v2 упаковывает исходники и ресурсы, читает прежний v1.
  Payload установщика содержит CLI/LSP, совместимые команды, manifest с SHA-256,
  оригинальный логотип и шрифт с лицензией. Упаковщик не содержит логики установки.

## Установщик на Skrumi

`installer/main.skm` реализует окно, параметры, прогресс, журнал, подтверждение
выхода, обработку ошибок и headless-режим. `installer/transaction.skm` реализует
всю прикладную логику: проверку владения файлами, staging, backup, журнал,
установку, обновление, удаление, PATH, проверку CLI, отмену и восстановление.
Python используется только в сборке и тестах; специализированного C++ движка
установки нет. Сборка: `packaging/build_gui_installer.py` поверх `skrumi build`.

Журнал записывается до публикации файлов. Отдельный этап изменения окружения
позволяет отменить операцию до commit и восстановить PATH после аварийного выхода.
Изменённые управляемые файлы блокируют обновление и сохраняются при удалении;
неуправляемые файлы не перезаписываются. Соседний OS lock исключает второй
экземпляр установщика для того же каталога.

Дополнительные тесты подтвердили отказ commit при недоступном журнале,

## Границы гарантий

Установка не атомарна целиком: между заменами отдельные файлы могут быть
недоступны, поэтому CLI не следует запускать во время обновления. SHA-256
проверяет соответствие вложенному manifest, но не удостоверяет издателя файла.
Проверка ссылок не является защитой от конкурентной подмены каталогов другим
процессом. При конфликте с внешними изменениями восстановление останавливается
и сохраняет backup для ручной проверки. Пустые каталоги после удаления/отмены
сохраняются; lock-файл остаётся намеренно. Повреждённый или отсутствующий журнал
пока требует ручного разбора без автоматического удаления неизвестных файлов.

Дополнительные Linux-проверки: GUI-подтверждение восстановления, отмена обновления
через системное закрытие окна с побайтовым восстановлением файлов, нехватка места
на отдельном 96-МиБ tmpfs и отказ записи при публикации. Пустой каталог транзакции
без журнала восстанавливается; неизвестные файлы сохраняются. Конфликт профиля
не мешает восстановить прежние бинарники, но журнал остаётся до разрешения конфликта.

Публичные `registry_user_snapshot`, `registry_user_compare_exchange` и
`registry_user_remove_empty_key` добавлены для строковых значений HKCU Software.
Регистрационная политика подключена к журналу формата 3 в `installer/integration.skm`; проверена на Windows runner для commit abbef4e.

Описание поставки, сохраняемой программы обслуживания и миграции старых установок:
[GUI_INSTALLER.md](GUI_INSTALLER.md). Новые исходники `std` входят в payload; LSP
можно отключить через GUI или `--no-lsp`. Поддержан импорт прежних Windows JSON
и Linux SHA-256 манифестов с проверкой всех управляемых файлов.
