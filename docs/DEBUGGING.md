# Отладка программ FoxLang

В FoxLang встроен отладчик. Он работает по протоколу Debug Adapter Protocol (DAP), поэтому
им пользуются из VS Code, Kate и Zed одинаково: ставите точку останова, запускаете
программу под отладчиком и смотрите стек, переменные и выражения.

## Что умеет отладчик

* **Точки останова** в любом файле программы, в том числе в подключённых через `include`.
  Точка на пустой строке или комментарии переносится на ближайший оператор ниже.
* **Условные точки** (`i == 3`, `name != ""`): остановка, только когда условие истинно.
  Условие — обычное выражение FoxLang типа `bool`.
* **Счётчик срабатываний** (hit count): `5` — остановиться на пятом проходе,
  `>= 5` — начиная с пятого, `% 10` — на каждом десятом.
* **Лог-точки**: вместо остановки печатают сообщение, выражения в фигурных скобках
  вычисляются: `i = {i}, имя = {name}`.
* **Шаги**: с заходом в функцию (Step Into), через функцию (Step Over), выход из
  функции (Step Out), продолжение и пауза.
* **Остановка на ошибке выполнения**: программа останавливается на операторе, где
  произошла ошибка (выход за границы массива, деление на ноль, неверный тип, `throw`),
  пока все переменные ещё на месте. Фильтр «Необработанные ошибки» (включён по
  умолчанию) останавливает на ошибках, которые не перехватит `try`, фильтр
  «Перехваченные ошибки» — и на тех, что обработает `catch`.
* **Стек вызовов**: функции с файлами и строками, нижний кадр — `программа`.
* **Переменные**: локальные (параметры и переменные функции и вложенных блоков,
  внутренние скрывают внешние с тем же именем) и глобальные. Массивы, словари и
  структуры раскрываются по элементам, ключам и полям, большие массивы — порциями.
* **Изменение значений**: переменную, элемент массива, значение словаря или поле
  структуры можно поменять прямо в панели переменных; значение — выражение FoxLang (`42`, `"текст"`, `n * 2`).
* **Выражения**: наблюдение (Watch), подсказка при наведении и консоль отладки.
  В консоли можно выполнять и операторы: `total = 0`, `print(items)`.

## VS Code

Нужны расширение FoxLang и FoxLang 6.4 или новее.

* **F5**, пункт «FoxLang: отладить программу» в меню кнопки ▶ в заголовке редактора
  или в контекстном меню запускает под отладчиком главный файл программы
  (`foxlang.run.entryFile`) или открытый файл.
* Программа работает в отдельном терминале «FoxLang: отладка»: `input()` читает из
  него, `print()` и цвета терминала выводятся туда же, графические окна открываются
  как обычно. Ошибки и лог-точки видны в консоли отладки.
* Для постоянных настроек создайте `.vscode/launch.json`:

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "type": "foxlang",
      "request": "launch",
      "name": "FoxLang: main.fox",
      "program": "${workspaceFolder}/main.fox",
      "args": ["--verbose"],
      "cwd": "${workspaceFolder}",
      "stopOnEntry": false,
      "env": { "FOXLANG_LOG_LEVEL": "debug" }
    }
  ]
}
```

| Поле | Назначение |
|---|---|
| `program` | главный файл программы (обязательно) |
| `args` | аргументы программы, доступны через `os_args()` |
| `cwd` | рабочая папка; по умолчанию папка главного файла |
| `stopOnEntry` | остановиться на первом операторе |
| `env` | дополнительные переменные окружения |

Под капотом расширение открывает локальный порт и запускает в терминале
`foxlang debug-adapter --connect 127.0.0.1:<порт>`.

## Kate

1. Включите плагин **Отладчик** (Настройка → Настроить Kate → Модули).
2. `install.sh` сам кладёт настройки в `~/.config/kate/debugger/dap.json`. Вручную —
   скопируйте [`editors/kate/dap.json`](../editors/kate/dap.json) туда же или добавьте
   его секцию `foxlang` в свой файл.
3. На панели отладчика выберите профиль **foxlang → launch (debug)** (или
   **launch (stop on entry)**) и запустите отладку текущего файла.

Kate общается с `foxlang debug-adapter` через стандартные потоки, поэтому вывод
программы появляется на панели отладчика, а `input()` получает пустую строку.
Программы, которые читают ввод, удобнее отлаживать в VS Code или передавать им данные
через аргументы и файлы.

## Zed

Расширение FoxLang регистрирует отладчик **FoxLang**. Откройте панель отладки
(`debugger: start`) и выберите FoxLang, либо опишите сценарий в `.zed/debug.json`:

```json
[
  {
    "label": "FoxLang: main.fox",
    "adapter": "FoxLang",
    "request": "launch",
    "program": "$ZED_WORKTREE_ROOT/main.fox",
    "cwd": "$ZED_WORKTREE_ROOT",
    "args": [],
    "stopOnEntry": false
  }
]
```

Как и в Kate, вывод программы идёт в консоль отладки, а `input()` получает пустую строку.

## Другие редакторы

Любой клиент DAP запускает адаптер командой `foxlang debug-adapter` (протокол через
stdin/stdout) и передаёт в запросе `launch` поля `program`, `args`, `cwd`,
`stopOnEntry`. Вариант `foxlang debug-adapter --connect host:port` подключается к
клиенту по TCP и оставляет программе её терминал.

## Что стоит знать

* Пока программа стоит на точке останова, её графическое окно не перерисовывается и
  не отвечает: кадры рисует сама программа.
* Пауза срабатывает на следующем операторе. Если программа ждёт внутри встроенной
  функции (`input()`, `wait()`, HTTP-запрос, ожидание клиентов сервера), она
  остановится, когда функция вернётся.
* Вычисление выражений выполняет код программы: `save()` в консоли действительно
  сохранит файл, а изменённые переменные останутся изменёнными.
* Верхний уровень подключённых модулей выполняется только ради объявлений, поэтому
  точки останова ставят внутри функций модулей, а в главном файле — где угодно.
* Отладчик понимает файлы программы на диске. Код встроенных модулей (`using ui;`)
  показывается в стеке вызовов и открывается по щелчку, но точки останова в нём не
  ставятся.
* Без отладчика интерпретатор ничего не платит: проверка «подключён ли отладчик»
  стоит одно сравнение на блок и на вызов.
